# Required adjustments for 0.0.16

0.0.16 changes client loop control and server delivery-result APIs. Apply following changes when upgrading from 0.0.15.

## Required

- `BaseClient.spin()` now returns `on_receive()` result. It raises `ClientExit` when disconnected and `GrpcEmpty` when timed out. A non-blocking empty queue raises `queue.Empty`; handle these exceptions instead of checking for `False`.
- `BaseClient.spin_forever()` no longer stops when `on_receive()` returns `False`. Raise `StopSpin` from `on_receive()` to stop loop while keeping client connected.
- `DataRegister.add_data_for_message_name()` now returns `DeliveryResult`, not `(delivered, dropped)`. Read `.delivered` and `.dropped`; import `DeliveryResult` when type checks or annotations need it.
- `DataRegister.add_notification_queue_for_message_name()` now returns `None`; do not use its previous integer return value.
- `on_receive()` may return any value. `spin()` passes value through; `spin_forever()` ignores it.

## Optional server configuration

- Set `ServerConfig.queue_warning_threshold` to control subscriber queue-growth warnings. Set it to `None` to disable warnings.
- `max_queue_elements=0` remains unbounded and provides no backpressure. Use a positive value when queue-full backpressure is required.
- `max_workers=None` now resolves to executor default worker sizing.

No protobuf or wire-format changes require client/server schema updates.
