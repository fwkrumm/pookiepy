# Required adjustments for 0.0.17

0.0.17 replaces global custom-protobuf registration with explicit dependency injection.

## Required

- Compile custom `.proto` files before starting pookiepy. Runtime compilation is no longer supported.
- Replace `compile_proto()`, `compile_and_register()`, `register_modules()`, `load_pb_modules_from_dir()`, and `resolve_modules()` with normal imports of generated modules.
- Construct `ProtoInterface(message_pb2, message_pb2_grpc)` and pass it as `proto_interface=` to every `BaseClient` and `BaseServer` using that schema.
- Construct custom messages from `proto_interface.message_pb2`, or pass the interface to `generate_message(proto_interface=...)`.

Custom client and server schemas must remain wire-compatible. Bundled-interface users need no changes. Application-managed schema-version validation is unchanged, and this release does not change the bundled wire schema.

## Protobuf envelope rename

This release renames the protocol envelope protobuf message from `Message` to
`PookieMessage`.

- Replace `message_pb2.Message()` with `message_pb2.PookieMessage()`.
- Regenerate bundled and custom protobuf Python, gRPC, and typing bindings from
	`message.proto`.
- Update type annotations and imports to use `PookieMessage` for the pookiepy
	envelope. `google.protobuf.message.Message` remains Google's generic protobuf
	base type.
- Custom interfaces must define `PookieMessage` and use it for both
	`Stream.DataChannel` request and response types.

This changes the gRPC descriptors from
`message.proto.v3.Message` to `message.proto.v3.PookieMessage`. Existing
clients and servers using the old descriptor cannot communicate with this
release. Do not mix old and new clients or servers; upgrade both sides and
regenerate custom interfaces together.
