# Required adjustments for 0.0.19

These notes cover synchronous server overload and error-handling changes.
For upgrades from older versions, also apply the earlier version-specific notes.
The protobuf wire schema and existing hook signatures are unchanged by these fixes.

## Connection overload

- Concurrent RPC admission is capped at the effective executor worker count. Set
  `ServerConfig.max_workers` for peak connections plus headroom.
- Excess clients now fail promptly with `GrpcResourceExhaustedError` rather than a
  handshake timeout. Update retry/error handling and use bounded backoff.
- Default sizing uses `os.process_cpu_count()` when available, so CPU-constrained
  processes on newer Python versions may have fewer workers than before.

## Errors and diagnostics

- Receive-worker application exceptions now terminate the RPC with INTERNAL; clients
  receive `GrpcConnectionError` instead of an apparently successful stream ending.
- Full-queue diagnostics now use WARNING. Full-queue and queue-growth warnings share
  one five-second cooldown per register, so logs sample affected subscribers rather
  than list every overloaded queue. Do not derive exact loss counts from log lines;
  manual routing returns `DeliveryResult` directly.

## Unchanged defaults and extension points

No migration is required for queue or logging defaults: notification queues remain
unbounded (`max_queue_elements=0`), and file logging retains INTERNAL_DEBUG tracing.
Finite queue bounds and reduced tracing remain explicit configuration choices, not
default performance optimizations. Existing synchronous hooks, repeated `on_shutdown()`
calls, and the polling-based stream loop are preserved. No new delivery hook or
receive-thread join setting is introduced.
